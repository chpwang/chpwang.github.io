Chapter 1 - Toys

这章介绍表达式的各种基础概念和后续要用的操作符（primitive operations）：
car ，cdr ，cons ，null? 和 eq?
本章标题 Toys 也许就指这些 primitive operations ，后续的概念和代码都会用到

An S-expression is either an atom or a collection of S-expressions enclosed by parentheses.

W’s summary
The Law of Car
The primitive car is defined only for non-empty lists.
The Law of Cdr
The primitive cdr is defined only for non-empty lists.
The cdr of any non-empty is always another list.
The Law of Cons
The primitive cons takes two arguments.
The second argument to cons must be a list.
The result is a list.
The Law of Null?
The primitive null? is defined only for lists.
The Law of Eq?
The primitive eq? takes two arguments.
Each must be a non-numeric atom.

Note:
“cdr” is pronounced “could-er”.
(cons a l) is read: “cons the atom a onto the list l.”

(define lat?    ; a lat is a list of atoms
  (lambda (l)
    (cond
      [(null? l) #t]
      [(atom? (car l)) (lat? (cdr l))]
      [else #f])))


(define member?
  (lambda (a lat)
    (cond
      [(null? lat) #f]
      [else
       (or (equal? a (car lat))       ; eq? → equal?

Chapter 5 - *Oh My Gawd*: It’s Full of Stars

前面章节的递归函数处理的是链表结构的数据：list 内元素都是 atom ；
本章开始是树结构（tree）：list 内元素都是 list 了；
因此 (car l) 和 (cdr l) 两部分都要递归；
处理这类链表中包含链表的数据结构的递归函数都带星号 * ，如 rember* ；

All *-functions work on lists that are either

  • empty,
  • an atom consed onto a list, or
  • a list consed onto a list

基本上就是把前几个章节的递归函数都改成星号函数

(define rember*      ; "rember*" is pronounced "rember-star"
  (lambda (a l)
    (cond
      [(null? l) '()]
      [(atom? (car l))
       (cond
         [(eqan? a (car l))
          (rember* a (cdr l))]
         [else
          (cons (car l)
                (rember* a (cdr l)))])]
      [else

; S-expressions that does not contain the empty list.

  (lambda (l)
    (cond
      [(atom? (car l)) (car l)]
      [else

(define eqlist?
  (lambda (l1 l2)
    (cond
      [(and (null? l1)
            (null? l2))
       #t]
      [(or (null? l1)
           (null? l2))
       #f]
      [(and (atom? (car l1))
            (atom? (car l2)))
       (and (eqan? (car l1)
                   (car l2))
            (eqlist? (cdr l1)
                     (cdr l2)))]
      [(or (atom? (car l1))
           (atom? (car l2)))
       #f]
      [else
       (and (eqlist? (car l1)
                     (car l2))
            (eqlist? (cdr l1)
                     (cdr l2)))])))

前面的递归函数都是 Directly Recursion（函数定义中调用自己）
下面首次出现 Mutually Recursion（多个函数在定义中相互调用）

eqlist? 和 equal? 相互调用

; An S-expression is either an atom or 
; a (possibly empty) list of S-expressions
; equal? determines whether two S-expressions are the same

; define equal? in terms of eqlist?
(define equal?
  (lambda (s1 s2)
    (cond
      [(and (atom? s1)
            (atom? s2))
       (eqan? s1 s2)]
      [(or (atom? s1)
           (atom? s2))
       #f]
      [else
       (eqlist? s1 s2)])))


; now rewrite eqlist? using equal?
(define eqlist?
  (lambda (l1 l2)
    (cond
      [(and (null? l1)
            (null? l2))
       #t]
      [(or (null? l1)
           (null? l2))
       #f]
      [else
       (and (equal? (car l1)
                    (car l2))
            (eqlist? (cdr l1)       ; equal? works too here
                     (cdr l2)))]))) ; for all lists are S-expressions
                                    ; and for equal? calls eqlist? in else

有了 equal? 之后，当前除了 eqan? 之外的所有函数中的 eq?（非数字比较） 和 =（数字比较）都可以用 equal? 来替换了。因为 equal? 里调用的 eqan? 就覆盖了数字和非数字两种情况的比较。

Chapter 6 - Shadows

这章讲算术表达式（arithmetic expression）。

An arithmetic expression is either an atom (including numbers), or two arithmetic expressions combined by , or

算数表达式是后续的解释器（interpreter）要支持的基本语言结构之一。其他基本语言结构还包括变量（variable），函数（function），调用（call）和数字常量（numbers）。书中从日常常见的中缀表达式（infix）开始介绍，然后过渡到前缀表达式（prefix）。
前缀表达式正是 Scheme 的表达式语法（S-expression）所采用的方式，因为它让语法更具统一性和规律性（所有操作符都在第一个位置），解释器也会因此变得非常简单。

中缀表达式：(9 + 19 + 29)
前缀表达式：(+ 9 19 29)

; numbered? determines whether a representation of
; an arithmetic expression contains only numbers besides
; +, × and ↑
(define numbered?
  (lambda (aexp)    ; aexp stands for "arithmetic expression"
    (cond
      [(number? aexp) #t]
      [else
       (and (numbered? (car aexp))  ; here use infix notation
            (numbered? (car (cdr (cdr aexp)))))])))
The Seventh Commandament
Recur on the subparts that are of the same nature:
• On the sublists of a list.
• On the subexpressions of an arithmetic expression.

本章出现了最简易的解释器函数 value ，后面复杂的解释器就是通过 value 来逐步扩展的。

(define value
  (lambda (nexp)    ; nexp stands for "numbered arithmetic expression"
    (cond
      [(atom? nexp) nexp]
      [(eq? (operator nexp) '+)
       (+ (value (1st-sub-exp nexp))
          (value (2nd-sub-exp nexp)))]
      [(eq? (operator nexp) '×)
       (× (value (1st-sub-exp nexp))
          (value (2nd-sub-exp nexp)))]
      [else
       (↑ (value (1st-sub-exp nexp))
          (value (2nd-sub-exp nexp)))])))


; use help functions to hide the representation
; so we can change notation to infix or prefix (or others)
; without affecting upper-level code (in this case: value)
(define 1st-sub-exp
  (lambda (aexp)
    (car (cdr aexp))))

(define 2nd-sub-exp
  (lambda (aexp)
    (car (cdr (cdr aexp)))))

(define operator
  (lambda (aexp)
    (car aexp)))
The Eighth Commandament
Use help functions to abstract from representation.

这里还展示了如何使用帮助函数（help function）建立抽象层。这样就不必考虑底层的语法到底是中缀还是前缀表达式了。帮助函数会取到对应的部分。语法的改变不影响上层代码，即 value 不受影响。

从帮助函数的抽象（Data Abstraction）进一步引出，我们之前用的数字（numbers）和布尔值（#f 与 #t）也都是抽象，或者说都是一种符号（representation）。我们可以用阿拉伯数字（arabic representation）以外的符号表达数字，比如括号：

() 表示数字 0 的概念
(()) 表示数字 1 的概念
(() ()) 表示数字 2 的概念
(() () ()) 表示数字 3 的概念

用了新符号（representation）后，只要改抽象层函数即可，上层代码无需改：

zero? , add1 和 sub1

(define sero?
  (lambda (n)
    (null? n)))


(define edd1
  (lambda (n)
    (cons '() n)))


(define zub1
  (lambda (n)   ; n can't be sero (null)
    (cdr n)))

这里其实开始涉及计算的本质了：计算的本质就是解释。

观察可以发现，我们的新符号（括号列表）之所以能表示数字的概念，其实是依靠我们同时定义的 sero? , edd1 和 zub1 这些（帮助）函数来建立的。我们靠这三个函数解释了它（括号列表），于是它有了数字的概念。进一步地，有了计算的概念和对应的计算结果。

要注意区分符号（representation）和它指代的意义这两个概念。符号不是数据或概念本身。
符号可以变（比如可中缀、可前缀），但 1st-sub-exp 的概念是不变的。它永远能取到对应的内容。
如果没有做好这种区分（抽象），改变符号（representation）就可能破坏上层代码。

  • Moses Schönfinkel（1889–1942）：逻辑学家。1924 年发表论文，系统介绍了将多参数函数转换为一系列单参数函数的思想，也是组合逻辑（Combinatory Logic）的先驱。

  • Haskell Brooks Curry（1900–1982）：美国数学家、逻辑学家，进一步发展了组合逻辑。后来这种函数转换技术以他的姓氏命名为 Currying。Curry 本人也承认这一思想来自 Schönfinkel。
